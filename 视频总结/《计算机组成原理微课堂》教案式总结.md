## 一、先建立全局图

计算机组成原理研究的核心问题可以压缩成一条链：

```text
信息如何表示
    ↓
信息如何存放、如何被找到
    ↓
运算器如何处理二进制数据
    ↓
指令如何描述“做什么”和“对谁做”
    ↓
CPU如何取指、译码、执行并控制数据流
    ↓
CPU、存储器和I/O设备如何通过总线协同
```

整套课程实际上是在逐层搭建一台计算机：

1. **数据表示**规定比特如何解释为整数、浮点数、字符、图像、音频等信息。
2. **运算器**规定这些比特怎样完成加减乘除和逻辑运算。
3. **存储器**规定数据放在哪里、怎样按地址取出，以及怎样用层次化结构提高速度。
4. **指令系统**把运算器和存储器能够做的事情编码成机器指令。
5. **CPU**用数据通路搬运数据，用控制器发出时序和控制信号，使一条指令真正执行。
6. **流水线**把多条指令的不同阶段重叠起来，提高吞吐率。
7. **总线和I/O**把CPU、内存、外设组织成一个可通信、可响应的系统。

学习时最重要的主线不是背名词，而是持续追问：**数据现在在哪里？它是什么编码？下一步由谁搬运？由谁控制？这一动作怎样提高速度，代价是什么？**

## 第一章 计算机系统的组成、发展与性能

### 1. 从“装机”进入“组成原理”

课程导论先用 CPU、内存、显卡、固态硬盘、主板、电源、输入输出设备等日常部件建立直觉：初学者并不陌生的是硬件外形和用途，而组成原理要解释的是底层机制：

- 数字、文本、图像、音频、视频怎样变成二进制数据；
- 二进制数据怎样存进存储器；
- CPU怎样从内存取出指令和数据；
- 运算器怎样处理数据；
- 硬件部件怎样由控制信号协调起来。

这也解释了它为什么和数据结构、操作系统、计算机网络并称计算机专业的基础课程：组成原理负责把“程序运行”落到数据、指令、部件和时序上。

### 2. 计算机系统的组成

计算机系统由**硬件系统**和**软件系统**组成。

- 硬件是看得见、能执行物理动作的实体，包括运算器、控制器、存储器、输入设备和输出设备。
- 软件是控制硬件完成任务的程序、数据和相关文档，包括系统软件和应用软件。
- 操作系统位于硬件和应用软件之间，向上提供抽象接口，向下管理处理器、内存、文件和设备。

从功能上看，主机中的 CPU 负责运算和控制，主存保存正在运行的程序和数据，外存长期保存信息，I/O 设备负责把系统和外界连接起来。

### 3. 计算机的发展脉络

课程用器件技术的演进说明计算机为什么越来越小、越来越快：电子管、晶体管、集成电路、大规模和超大规模集成电路。器件发展带来速度、容量、可靠性和成本的持续改善，也推动了从大型机、微型机到个人计算机、移动设备和云计算平台的演进。

技术进步不是单纯“频率变高”，还包括并行执行、缓存层次、流水线、多核处理器、专用加速器和更高效的互连结构。

### 4. 计算机系统的层次结构

从上到下可以这样看：

```text
应用程序
高级语言
汇编语言
机器指令
操作系统与指令系统接口
CPU、存储器、总线、I/O硬件
数字逻辑门与电子器件
```

每一层都向上层提供抽象接口，同时把上层请求翻译为更底层的操作。程序员写下 `a = b + c`，最终会变成机器指令；机器指令又会被控制器分解为寄存器装入、总线传送、ALU 运算和结果写回等微操作。

### 5. 存储程序工作原理

现代计算机遵循存储程序思想：指令和数据以二进制形式存放在存储器中，CPU按照程序计数器给出的地址取指令，译码后执行，再更新程序计数器取得下一条指令。

最基本的指令周期是：

```text
取指 → 译码 → 取操作数 → 执行 → 访存（必要时）→ 写回
```

控制器通过时序信号让这些动作按正确顺序发生。程序改变的本质，是改变存储器中的指令和数据，或者改变下一条指令的地址。

### 6. 性能指标：不要只看主频

常见指标包括机器字长、存储容量、运算速度、数据通路宽度和吞吐率。CPU执行时间的核心公式是：

```text
CPU时间 = 指令条数 IC × 平均每条指令周期数 CPI × 时钟周期时间
        = IC × CPI / 时钟频率 f
```

因此性能不仅取决于频率，还取决于指令条数和 CPI。主频高但 CPI 大，或者程序需要执行更多指令，未必更快。

常见相关指标：

- **时钟周期**：相邻时钟脉冲的时间间隔，等于 `1/f`。
- **CPI**：平均执行一条指令需要的时钟周期数。
- **MIPS**：每秒执行多少百万条指令，常写作 `MIPS = f/(CPI × 10^6)`，但跨不同指令集比较时要谨慎。
- **吞吐率**：单位时间完成的任务量，适合描述流水线和批处理系统。
- **响应时间**：单个任务从开始到完成的时间，适合用户交互。

性能分析的正确顺序是先明确工作负载，再确定 IC、CPI、频率和存储访问代价，不能拿一个孤立指标代替整机性能。

## 第二章 计算机内部的数据表示

### 1. 为什么所有信息最后都是比特

数字电路容易稳定地区分两种状态，所以计算机采用二进制。文本可以用字符编码表示，图像可用像素和颜色分量表示，音频可用采样值表示，视频则是随时间变化的图像序列。信息类型不同，最终都要落成一串比特；区别在于解释这些比特的规则不同。

需要分清三件事：

1. **真值**：人希望表达的数学值或信息含义。
2. **机器数**：真值在计算机中的编码。
3. **定点/浮点格式**：机器数中小数点位置和字段的约定。

### 2. 进位计数制与转换

基数为 `r` 的数，各位按位权 `r^i` 展开。整数部分常用“除基取余、逆序排列”，小数部分常用“乘基取整、顺序排列”。二进制、八进制、十六进制之间因为 `8=2^3`、`16=2^4`，可以按 3 位或 4 位二进制直接分组转换。

要注意：十进制小数转二进制时可能出现无限循环小数，所以实际机器格式只能截取有限位并进行舍入，这正是浮点数误差的来源之一。

### 3. 定点数的四种编码

假设机器字长为 `n+1` 位，其中 1 位符号位，n 位数值位。

#### 原码

- 符号位 0 表示正，1 表示负；
- 数值位表示绝对值；
- `+0` 和 `-0` 有两种编码；
- n+1 位定点整数的原码范围为 `-(2^n-1) ~ +(2^n-1)`。

原码直观，但加减法不能直接把编码当普通二进制相加，必须先处理符号和绝对值大小。

#### 反码

- 正数反码等于原码；
- 负数反码是符号位不变、数值位按位取反；
- 同样存在两个零；
- 负数加法会产生循环进位，需要把最高位产生的进位加到最低位。

#### 补码

- 正数补码等于原码；
- 负数补码等于负数反码加 1，也可理解为按位取反后加 1；
- 只有一个零；
- 比原码、反码多表示一个最小负数；
- n+1 位定点整数补码范围是 `-2^n ~ 2^n-1`。

补码最重要的价值是把减法转化为加法：

```text
[x - y]补 = [x]补 + [-y]补   （结果保留规定的位数）
```

这样加法器只需要一套，硬件结构更简单。

#### 移码

移码把真值整体加上偏移量，常见定义为：

```text
[x]移 = x + 2^n
```

移码的 0 表示唯一，并且编码的无符号大小规律与真值大小规律一致，适合比较浮点数的阶码。移码通常用于定点整数形式的阶码，不要把“移码”误认为普通的左移。

#### 编码转换的稳健方法

做题时先看符号位：

1. 正数四种编码基本相同；
2. 原码负数先保留符号位，再取数值；
3. 反码负数数值位取反得到原码绝对值；
4. 补码负数先减 1 再按位取反，或直接按补码规则求真值；
5. 移码先减去偏移常数得到真值。

不要把“编码位串”与“真值的二进制表示”混为一谈。

### 4. 浮点数：用阶码换范围，用尾数换精度

定点数的小数点位置固定，表示范围有限。浮点数把一个数写成：

```text
N = M × R^E
```

其中 `M` 是尾数，决定有效数字和精度；`E` 是阶码，决定数量级和表示范围；`R` 是隐含约定的基数，通常为 2。

浮点数加减必须先对阶：

```text
比较阶码 → 小阶向大阶对齐 → 尾数相加减 → 规格化 → 舍入/检查溢出
```

规格化的目标是让尾数保持统一形式，例如二进制规格化正数写成 `1.M × 2^E`。规格化能尽量利用有限的尾数位，提高表示精度。

浮点表示有两类边界问题：

- 阶码过大，结果超出范围，发生上溢；
- 阶码过小，结果太接近 0，发生下溢，可能按 0 处理或使用非规格化数保留渐进下溢。

### 5. IEEE 754

课程画面用字段表和具体机器码例题说明 IEEE 754 单精度格式：

```text
| 符号 S：1位 | 阶码 E：8位 | 尾数 M：23位 |
```

规格化数的有效尾数隐含最高位 1，所以实际有效位为 24 位；阶码采用偏移常数 127 的移码形式。

对单精度规格化数，真值可写成：

```text
(-1)^S × (1.M) × 2^(E-127)
```

特殊编码：

- `E=0, M=0`：+0 或 -0；
- `E=0, M≠0`：非规格化数；
- `E=255, M=0`：正无穷或负无穷；
- `E=255, M≠0`：NaN，表示无定义数。

画面中的典型转换题是把十六进制机器码 `C1830000` 转为十进制值：先转 32 位二进制，再拆出符号位、阶码和尾数字段，判断阶码是否为全 0/全 1，最后按 IEEE 754 真值公式计算。做这类题时必须按字段顺序处理，不能直接把整个 32 位数当有符号整数。

浮点数的误差来自有限的尾数位和舍入。因而程序中不要轻易直接比较两个浮点数是否完全相等；对误差敏感的计算，应使用误差范围判断或采用定点/整数方案。

### 6. C 语言数据类型的连接

C 语言中的 `char`、`short`、`int`、`long` 属于定点整数；`float` 和 `double` 通常对应 IEEE 754 单精度和双精度。类型转换会涉及扩展、截断、符号解释和精度损失：

- 小类型转大类型通常要扩展符号位或补 0；
- 大类型转小类型可能截断高位；
- 整数转浮点可能因尾数位不足而失去精度；
- 浮点转整数通常截去小数部分，并可能发生范围溢出。

## 第三章 运算方法与运算器

### 1. 移位运算

- **逻辑左移/右移**：空出的位补 0，适合无符号数；
- **算术左移**：通常与逻辑左移相同，但要关注符号和溢出；
- **算术右移**：空出的高位补符号位，保持负数符号；
- **循环移位**：移出的位回到另一端，常用于位操作和编码处理。

移位本质上改变各位的权值。左移一位相当于乘 2，右移一位相当于除 2，但只有在不溢出、且舍入规则允许时才能这样理解。

### 2. 补码加减与溢出检测

补码加法直接按位相加，最高位进位丢弃。减法通过加上减数的相反数实现。溢出不是看最高位进位是否存在，而是看结果是否超出补码表示范围。

常用判断：

- 两个正数相加得到负数，溢出；
- 两个负数相加得到正数，溢出；
- 正负数相加不会发生补码加法溢出。

等价的硬件判断是：最高有效位的输入进位与输出进位不同则溢出。

### 3. 从逻辑门到加法器

逻辑代数描述 0/1 运算，基本门包括与、或、非，常见复合门包括与非、或非、异或。异或在加法器中尤其重要，因为：

```text
和位 = A ⊕ B ⊕ Cin
进位 = AB + Cin(A ⊕ B)
```

一位全加器处理两个加数位和来自低位的进位。把多个全加器串起来就得到多位加法器。

- **串行进位加法器**：每一位等待前一位进位，结构简单但延迟随位数增长。
- **先行进位加法器**：利用生成函数和传递函数并行预测进位，速度更快但逻辑更复杂、硬件开销更大。

这体现了组成原理常见的取舍：提高速度通常需要更多硬件、更多连线或更复杂的控制。

### 4. 乘法器

无符号乘法可以看成按乘数各位选择被乘数、移位并累加。原码乘法先分别处理符号和绝对值；补码乘法则直接利用补码规则处理正负数，减少软件和硬件之间的转换。

阵列乘法器把部分积排列成规则的加法器阵列：

- 无符号阵列结构规则，适合并行产生部分积；
- 补码阵列需要处理符号扩展和负权项，结构更复杂。

乘法题和硬件题要同时关注三个量：部分积如何生成、每一步如何移位、结果位数是否足够。

### 5. 除法器

原码除法用绝对值运算，最后再确定符号。课程重点比较恢复余数法和不恢复余数法：

- **恢复余数法**：试减后若余数为负，就恢复原余数并记商 0；若非负则记商 1。
- **不恢复余数法**：不立即恢复，而根据上一步余数符号决定下一步加法或减法，减少恢复动作。

补码除法直接处理带符号数，判断商位时要特别注意余数符号和符号扩展。手算时建议列出每轮的余数寄存器、商寄存器和被除数寄存器，不要只写最终商和余数。

### 6. 浮点运算

浮点加减的硬件流程是对阶、尾数运算、规格化、舍入和异常判断；乘除的阶码分别相加或相减，尾数分别相乘或相除，最后再规格化。IEEE 754 还要处理 0、无穷、NaN、非规格化数和舍入。

### 7. 运算器的整体结构

运算器不只是一个 ALU，而是由 ALU、通用寄存器、移位器、状态寄存器、暂存寄存器和数据通路组成。ALU负责运算，寄存器负责暂存操作数和结果，状态寄存器保存进位、溢出、零、负等标志，控制器决定每一步选择哪条数据路径。

## 第四章 存储器系统

### 1. 存储器的三个基本问题

存储器设计总是在平衡：

- **容量**：能保存多少数据；
- **速度**：访问一次需要多久；
- **价格/功耗**：单位容量成本和能耗如何。

存储系统因此形成层次结构：

```text
寄存器 → Cache → 主存 → 外存/辅存
速度越来越慢，容量越来越大，单位成本通常越来越低
```

利用程序的时间局部性和空间局部性，把最近用过或附近的数据放到更快的层次，就能获得接近高速存储器的平均效果。

### 2. 主存结构、地址译码与数据存放

主存由许多存储单元组成，每个单元有唯一地址。地址线决定可寻址单元数量，数据线决定一次传送的位数，控制线决定读、写、片选等操作。

地址译码把 CPU 发出的地址转换为某一行、某一列或某一片存储芯片的选择信号。画面中的译码结构体现了“地址不是数据，而是选择存储位置的控制信息”。

多字节数据的存放要明确字节地址、字长和大小端：小端把低有效字节放在低地址，大端把高有效字节放在低地址。做主存编址题时先确认“按字节编址还是按字编址”，再计算容量和地址范围。

### 3. SRAM、DRAM 与 ROM

#### SRAM

SRAM 存储元通常由交叉耦合反相器构成锁存状态，读写速度快，不需要周期性刷新，但每个比特所需晶体管较多、集成度较低、成本较高，常用于 Cache。

#### DRAM

DRAM 常用一个晶体管和一个电容保存一位信息，集成度高、容量大、成本低，但电容会漏电，需要定期刷新；读操作还可能破坏原内容，因此读取后要恢复。

DRAM 的行列地址复用可以减少引脚数量，刷新则按行进行。同步 DRAM、DDR 等发展方向都在改善带宽和时序效率。

#### ROM

ROM 用于保存掉电后仍需保留的固定或半固定信息。不同 ROM 的区别主要在于写入方式、可擦除方式和可重写次数。

### 4. 主存扩展与 CPU 连接

存储芯片常见扩展有三种：

- **位扩展**：增加数据位宽，多片芯片共享地址和控制线，分别提供不同数据位；
- **字扩展**：增加可寻址字数，用高位地址经过译码选择不同芯片；
- **字位同时扩展**：同时增加字数和位宽。

做扩展题时先写目标容量和单片容量，再分别比较“字数”和“每字位数”，最后决定地址线、数据线、片选线和译码器的连接。

### 5. 主存系统的优化

- **双端口存储器**：允许两个端口同时访问，提高并行性，但硬件复杂。
- **单体多字存储器**：一次取出多个连续字，适合连续访问。
- **多体交叉存储器**：把连续地址分布到多个存储体，使多个体交错工作，提高带宽。

高位交叉更适合按块分区；低位交叉能让连续地址落到不同存储体，适合连续流水访问。判断地址属于哪个存储体，要先看题目规定的交叉方式和地址字段。

### 6. Cache：用局部性换速度

Cache 保存主存中近期最可能再次访问的数据块。CPU 地址通常拆成：

```text
| Tag 标记 | Index 组/行号 | Offset 块内地址 |
```

访问流程：

1. CPU 给出主存地址；
2. 根据 Index 找到 Cache 行或组；
3. 比较 Tag 和有效位；
4. 命中则直接取数；
5. 未命中则从下一级存储器调入整个块，必要时替换旧块，再完成访问。

映射方式：

- **直接映射**：每个主存块只能放到一个 Cache 行，查找简单、成本低，但冲突多；
- **全相联映射**：任意主存块可放到任意行，冲突少，但需要同时比较多个 Tag；
- **组相联映射**：先按组定位，再在组内任意放置，是性能和成本的折中。

Cache 题的固定步骤是：先由容量和块大小算行数/组数，再把主存地址拆成 Tag、Index、Offset，最后沿访问序列判断命中、缺失、替换和 Cache 内容变化。

写策略也要分清：

- **写直达**：同时写 Cache 和主存，简单可靠，但写流量大；
- **写回**：只写 Cache，并用脏位记录，替换时再写回主存，减少写流量但控制复杂；
- **写分配/非写分配**：写缺失时是否先把对应块调入 Cache。

替换算法常见 LRU、FIFO、随机等。LRU利用近期访问历史，命中率通常较好，但需要记录使用顺序。

### 7. 虚拟存储器、页表与 TLB

虚拟存储器把程序看到的虚拟地址空间与物理主存分离。分页系统把虚拟地址分成：

```text
虚页号 VPN | 页内偏移
```

页表把虚页号映射到物理页框号，页内偏移保持不变。若页不在主存，就发生缺页，需要从外存调入页面，并更新页表。

TLB 是页表项的高速缓存。带 TLB 的访问流程是：

```text
虚拟地址
  ↓
查 TLB：命中则快速得到页框号
  ↓ 未命中
查页表：得到页框号并更新 TLB
  ↓
形成物理地址
  ↓
查 Cache
  ↓
命中取数；未命中再访问主存
```

因此一次虚拟地址访问可能涉及 TLB、页表、Cache 和主存四个层次。做题时要严格区分：页内偏移由页大小决定，Cache 块内偏移由块大小决定，Cache Index 由行数/组数决定，Tag 是剩余高位。

## 第五章 指令系统

### 1. 指令做什么、对谁做

一条指令至少要回答两个问题：执行什么操作，以及操作数在哪里。指令的一般结构是：

```text
操作码字段 + 地址码字段（或寄存器、立即数等字段）
```

指令字长、操作码位数、地址字段数量相互制约。地址字段越多，一条指令能直接指定的操作数越多，但指令字会变长；操作码越多，可表示的操作类型越丰富，但地址字段可用位数减少。

### 2. 操作码设计

定长操作码译码简单、取指方便；变长操作码可以在有限指令字长下容纳更多指令，但译码复杂。扩展操作码通过让不同格式的地址字段承担不同数量的操作码位，实现多种指令格式共存。

### 3. 寻址方式

寻址方式决定有效地址 EA 如何形成。常见方式包括：

- **立即寻址**：操作数就在指令中，速度快但范围受字段限制；
- **直接寻址**：地址字段直接给出有效地址；
- **间接寻址**：地址字段指向存放有效地址的存储单元；
- **寄存器寻址**：寄存器号指明操作数所在寄存器；
- **寄存器间接**：寄存器中保存有效地址；
- **基址寻址**：基址寄存器加位移，适合程序重定位；
- **变址寻址**：变址寄存器加位移，适合数组访问；
- **相对寻址**：程序计数器加位移，适合分支和位置无关代码；
- **堆栈寻址**：隐含使用栈顶指针，适合函数调用和表达式求值。

指令寻址主要解决下一条指令在哪里，通常由顺序执行的 PC 自动加上指令长度，或由转移指令装入新地址。操作数寻址则解决数据在哪里。两者不要混淆。

### 4. 指令的操作类型

指令通常包括数据传送、算术运算、逻辑运算、移位、比较、转移、调用返回、输入输出和处理器控制等类型。指令系统的设计要在功能丰富、编码紧凑、硬件实现复杂度和执行效率之间折中。

### 5. CISC 与 RISC

- **CISC**：指令功能复杂、格式多、寻址方式丰富，单条指令可能完成较多工作；
- **RISC**：指令数量较少、格式规整、寻址方式简单，强调寄存器操作、流水线和编译器配合。

现代处理器并非简单二选一：复杂指令常会在内部翻译为更规整的微操作，关键仍是指令系统、编译器和微结构怎样协同。

### 6. 指令系统综合题的通用方法

1. 先画指令格式，标出操作码、寄存器号、地址码和立即数字段；
2. 判断指令字长、机器字长、存储编址单位；
3. 写出每种寻址方式的 EA 公式；
4. 沿取指、读寄存器、访存、执行和写回过程追踪数据；
5. 对转移指令重点追踪 PC，对访存指令重点追踪有效地址。

## 第六章 CPU

### 1. CPU 的组成

CPU 由运算器、控制器、寄存器组和内部数据通路组成。控制器产生控制信号，数据通路负责数据在寄存器、ALU、存储器接口之间流动。常见寄存器包括 PC、IR、MAR、MDR、通用寄存器和状态寄存器。

### 2. 指令执行过程与指令周期

基本流程是：

```text
取指：PC → MAR，主存读，MDR → IR，PC更新
译码：控制器分析IR中的操作码和地址字段
取数：按寻址方式获得操作数
执行：ALU、移位器或控制逻辑完成动作
访存：读写主存或I/O（需要时）
写回：把结果写入寄存器或存储器
```

指令周期可细分为取指周期、间址周期、执行周期和中断周期。每个阶段又由若干节拍组成，节拍中发生一组彼此不冲突的微操作。

### 3. 数据通路：CPU 内部单总线

单总线结构让多个寄存器共享一条内部传送通道，但同一时刻通常只能有一个部件向总线输出，目标寄存器则由控制信号装入。ALU 的两个输入可能需要暂存寄存器，结果再通过总线写回。

分析数据通路题时，不要只写“执行加法”，而要写出完整微操作序列，例如：

```text
R1 → 总线 → 暂存寄存器A
R2 → 总线 → 暂存寄存器B
A + B → ALU → 暂存寄存器C
C → 总线 → R0
```

还要检查每一步是否存在总线冲突、是否缺少暂存寄存器、是否需要等待存储器响应。

### 4. 控制器与时序

CPU 的控制方式需要回答“什么时候发出哪个信号”。课程先介绍时序发生器，再比较硬布线控制器和微程序控制器。

#### 硬布线控制器

由逻辑门、触发器和译码器构成，控制信号由指令译码、时序状态和条件标志组合产生。速度快，但指令系统或数据通路改变时，电路修改困难。

#### 微程序控制器

把每个机器指令的控制过程写成微程序，微指令中包含操作控制字段和下一个微地址的形成方式。微程序控制器由控制存储器、微地址寄存器、微指令寄存器、地址转移逻辑等组成。

设计流程是：

```text
分析机器指令 → 列出微操作 → 编排微指令 → 设计微地址转移 → 写入控制存储器
```

水平型微指令控制位多、并行性高、字长长；垂直型微指令编码程度高、字长短、解释过程更复杂。字段表示方法还会影响同一节拍能否并行发出多个控制信号。

### 5. 异常与中断

异常/中断打破顺序执行，把 CPU 转去执行处理程序，处理完成后再恢复原程序。

- **异常**通常由当前指令执行引起，如非法操作、缺页、算术溢出；
- **中断**通常来自外部设备或外部事件，和当前执行指令相对独立；
- 可屏蔽中断可以暂时禁止，不可屏蔽中断通常用于紧急事件。

处理过程包括保存断点和必要状态、识别中断源、转入中断服务程序、执行服务、恢复现场和返回原程序。多重中断还要考虑优先级和中断屏蔽。

为 CPU 增加中断功能时，数据通路需要增加保存 PC/状态、装入入口地址、处理中断请求的路径；硬布线或微程序控制器也要增加中断判定、现场保存、服务程序入口和返回等控制步骤。

### 6. 指令流水线

流水线把指令执行划分为多个阶段，使不同指令同时处在不同阶段。理想情况下，流水线级数为 k、指令数为 n 时，完成时间从逐条执行的近似 `n×k` 个节拍降到 `k+n-1` 个节拍，吞吐率接近每拍完成一条指令。

流水线提高的是**吞吐率**，不一定减少单条指令的延迟。

流水线数据通路需要在级间加入流水寄存器，保存操作数、控制信号和中间结果，保证各阶段在时钟边界上正确衔接。

#### 三类冲突

- **结构冲突**：硬件资源不够，例如取指和访存同时争用同一存储器。解决办法是增加资源、分离指令/数据 Cache 或停顿。
- **数据冲突**：后一条指令需要前一条尚未写回的结果。常见类型是 RAW，解决办法包括暂停插入气泡、数据旁路、编译器调度。
- **控制冲突**：分支改变 PC，但流水线已经取入后续指令。解决办法包括预测、延迟分支、清空错误路径指令。

**插入气泡**简单但会降低吞吐率；**数据旁路**把执行阶段产生的结果直接送给后续阶段，减少等待，但需要额外连线、选择器和冲突判断。超流水线增加级数，多发射在一个周期发射多条指令，二者都能提高并行性，但也会加剧冲突和控制复杂度。

## 第七章 总线

### 1. 总线的作用与分类

总线是一组能被多个部件共享的传输线路和控制规则。典型总线由数据线、地址线和控制线组成。需要区分主设备和从设备：主设备发起事务，从设备响应事务。

总线标准通常规定机械特性、电气特性、功能特性和时间特性。总线可按功能、传输方向、时序方式、连接部件和数据线数量分类。

### 2. 总线性能

关键指标包括总线宽度、工作频率、传输周期、带宽、响应时间和负载能力。理论带宽可近似写作：

```text
带宽 = 每次传输的数据量 × 每秒传输次数
```

实际带宽会被仲裁、建立地址、等待从设备、校验和总线空闲时间折损。

### 3. 总线事务、仲裁与定时

一次总线事务通常包括请求总线、获得授权、发送地址和命令、传输数据、结束事务。多个主设备同时请求时，需要总线仲裁：

- 集中式仲裁由中央仲裁器决定谁使用总线；
- 分布式仲裁由各设备协同决定；
- 固定优先级响应快但可能让低优先级设备长期等待；
- 轮询或公平仲裁能避免饥饿，但控制更复杂。

总线定时规定地址、命令、数据和应答信号的先后关系。同步总线依赖统一时钟，异步总线依赖握手信号，后者适合速度差异较大的设备。

### 4. 信息传送方式和常用总线

并行传送一次传多位，短距离速度高但连线多、串扰和同步困难；串行传送逐位或按串行链路传输，适合长距离和高速互连。系统总线的设计最终服务于 CPU、主存和 I/O 设备之间的地址、数据和控制信息交换。

## 第八章 输入输出系统

### 1. I/O 系统的角色

外设的速度、格式、电气特性与 CPU 不同，不能让 CPU 直接面对每一种设备细节。I/O 系统通过设备控制器和 I/O 接口完成缓冲、状态保存、命令解释、数据格式转换和时序匹配。

常见接口寄存器包括：

- 数据寄存器：保存输入或输出数据；
- 状态寄存器：表示设备是否就绪、忙、出错；
- 控制寄存器：接收 CPU 发来的命令和控制位。

### 2. 程序直接控制/查询方式

CPU 反复读取设备状态，设备就绪后再传输数据。流程简单，但 CPU 必须不断查询，设备慢时会浪费大量处理器时间，适合简单、低速或早期系统。

### 3. 中断驱动方式

设备准备好或发生事件时主动提出中断请求，CPU 完成当前可中断指令后响应，保存现场并执行中断服务程序。相比查询方式，CPU 可以在设备等待期间执行其他程序。

需要掌握：

- 中断请求、响应和中断服务程序的关系；
- 单级中断和多重中断的流程；
- 中断优先级、中断屏蔽和现场保护；
- 中断向量如何帮助 CPU 找到服务程序入口。

### 4. DMA 方式

大量数据传输时，如果每个字节都由 CPU 处理中断，仍然会产生很大开销。DMA 控制器可以直接在 I/O 设备和主存之间传输数据，CPU 只需在开始时设置内存地址、传输计数和方向，传输完成或出错时再接收通知。

DMA 的关键过程是：

```text
CPU初始化DMA → DMA申请总线 → 获得总线控制权
→ 外设与主存直接交换数据 → 地址递增、计数递减
→ 传输完成，DMA释放总线并通知CPU
```

DMA 减少 CPU 参与次数，但会和 CPU 竞争总线及主存带宽。常见传送方式有停止 CPU 访问的成组传送、周期挪用和 DMA 与 CPU 交替访问等。

## 三、跨章节串起来：一条指令到底发生了什么

假设程序执行一条“把内存中的两个整数相加并写回”的指令，可以按下面的链条理解：

1. **编译器**把源程序转换成机器指令；
2. **指令格式**规定操作码、寄存器和地址字段；
3. **PC**给出指令地址，CPU 通过 Cache/主存取指；
4. **TLB 和页表**必要时把虚拟地址转换成物理地址；
5. **Cache**判断指令或数据是否命中；
6. **控制器**译码指令并发出时序控制信号；
7. **数据通路**把操作数送入寄存器和 ALU；
8. **运算器**用补码加法完成整数相加，并更新标志位；
9. **结果**通过内部总线写回寄存器或 Cache；
10. **Cache 写策略**决定何时把修改传播到主存；
11. 若是 I/O 数据，还可能通过总线和 DMA 在设备与内存间搬运。

这条链把八章内容连成一个整体：**表示决定意义，存储决定位置，指令决定动作，CPU决定时序，总线决定通信，I/O决定系统如何接触外界。**

## 四、重点题型的统一解题框架

### 1. 数据表示题

先确认位数、符号位、定点/浮点和编码类型，再求真值或编码。浮点题按“符号—阶码—尾数—特殊值判断—真值公式”处理。

### 2. 补码运算题

统一扩展到题目要求的位数；负数先求补码；按位相加；丢弃最高进位；最后根据符号变化或进位关系判断溢出。

### 3. Cache 题

先算块大小、行数、组数，再拆地址；按访问顺序维护有效位、Tag、脏位和替换次序。不要先看地址的十进制大小猜命中。

### 4. 页表/TLB/Cache 综合题

从虚拟地址开始，先看 TLB，再看页表，再形成物理地址，最后按物理地址访问 Cache。分别标出页内偏移和块内偏移，不能混用。

### 5. 指令格式和寻址题

先画字段，再写 EA；对每种指令依次写 PC、IR、MAR、MDR、寄存器和存储器的变化。地址字段是“编码信息”，有效地址是“真正访问的地址”，二者不总是相同。

### 6. CPU 数据通路题

把每个控制信号落实为一个微操作，逐拍检查谁向总线输出、谁从总线接收、ALU 两个输入是什么、结果写到哪里。

### 7. 流水线题

先画时间—空间图，再标出结构、数据和控制冲突；最后插入气泡或画旁路。重点是说明每个停顿为什么发生，而不是只数总周期数。

### 8. I/O 方式比较题

从 CPU 参与程度、数据传送主体、响应方式、适用场景和总线占用比较：查询最简单但最浪费 CPU；中断适合零散事件；DMA 适合高速大批量传输。

## 五、最容易混淆的概念

| 易混点 | 正确区分 |
|---|---|
| 原码、反码、补码 | 它们是机器编码，不是真值本身 |
| 移码与移位 | 移码是加偏移量的编码；移位是位串移动 |
| 溢出与进位 | 补码溢出看符号/最高位进位差异，不是单看有无进位 |
| 阶码与尾数 | 阶码控制范围，尾数控制精度 |
| Cache 缺失与缺页 | 前者发生在 Cache 层，后者发生在虚拟存储器层，代价不同 |
| TLB 与页表 | TLB 是页表项的高速缓存，不是完整页表的替代品 |
| Cache 块与页 | 块服务于 Cache，页服务于虚拟存储器，大小和映射规则不同 |
| 直接寻址与寄存器间接 | 直接寻址的地址在指令中，寄存器间接的地址在寄存器中 |
| 流水线延迟与吞吐率 | 流水线主要提高吞吐率，单条指令延迟未必降低 |
| 中断与 DMA | 中断是请求 CPU 处理事件，DMA 是控制器直接搬运数据 |

## 六、给初学者的学习与复习方案

### 第一轮：建立结构

按 p001-p009、p010-p021、p044-p083、p084-p132、p133-p154 的顺序快速看一遍，只问每一章解决什么问题，并画出“数据—存储—指令—CPU—总线—I/O”主线。

### 第二轮：补齐计算方法

重点练习补码、移码、IEEE 754、补码加减溢出、乘除法、主存扩展、Cache 地址拆分、页表/TLB、指令寻址、数据通路和流水线时序图。

### 第三轮：做综合题

每道题都强制写清四件事：

1. 已知的位数、容量、地址和时序；
2. 使用的编码或映射规则；
3. 中间过程中的数据流；
4. 最终结果及边界条件。

### 一页纸最终背诵骨架

```text
表示：原码/反码/补码/移码，IEEE754
运算：移位、补码加减、乘法、恢复/不恢复除法
存储：SRAM/DRAM，主存扩展，Cache，页表/TLB
指令：格式、操作码、寻址方式、操作类型
CPU：指令周期、数据通路、硬布线/微程序控制
并行：流水线、结构/数据/控制冲突及解决
互连：总线事务、仲裁、定时、带宽
I/O：查询、中断、DMA，CPU参与程度逐步降低
```

## 九、结语

学完整套课程后，应该能够从一条机器指令出发，解释它的编码、取指、地址转换、Cache 命中、寄存器传送、ALU 运算、控制信号、流水线停顿，以及它和总线、主存、I/O 的关系。真正掌握组成原理的标志，是能把“一个抽象的程序动作”还原成“数据在哪里、经过哪些部件、在什么时刻、由哪些控制信号驱动完成”。
